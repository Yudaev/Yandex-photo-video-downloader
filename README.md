# Yandex Photo & Video Downloader

Публичный проект расширения для Google Chrome, которое скачивает оригиналы фото и видео через веб-интерфейс страницы [«Фото» Яндекс Диска](https://disk.yandex.ru/client/photo), включая безлимитную автозагрузку.

## Назначение

Расширение предназначено для сохранения на компьютер фотографий и видео из безлимитной автозагрузки Яндекса. Основной сценарий — работать с файлами через страницу «Фото» в браузере, используя свой аккаунт Яндекса.

## Использование

1. Установить расширение в Google Chrome.
2. Войти в свой аккаунт Яндекса и открыть https://disk.yandex.ru/client/photo.
3. Нажать «Скачать все» над кнопкой «Загрузить» либо значок расширения.
4. Выбрать папку системным диалогом, отметить нужные типы файлов и нажать «Начать скачивание».
5. Оставить вкладку и панель открытыми до завершения. Для остановки нажать «Остановить скачивание».
6. После завершения или остановки применить исходные даты файлов командой для своей ОС из раздела [«Даты файлов»](#даты-файлов).

## Статус

Реализована последовательная загрузка через текущую авторизованную вкладку. Расширение обходит виртуальную фотоленту с подгрузкой при прокрутке, открывает каждый выбранный файл, читает имя и даты из кнопки «Информация» и нажимает штатную кнопку «Скачать». Ошибка предпросмотра не считается ошибкой оригинала.

Фиолетовая кнопка «Скачать все» открывает встроенную боковую панель Chrome. Браузер выделяет панели место и уменьшает ширину вкладки: панель не перекрывает Яндекс Диск. Значок расширения показывает и скрывает панель без новой вкладки. Сторона размещения панели задаётся в настройках Chrome; для размещения справа выберите правую сторону.

В боковой панели кнопка «Выбрать папку…» сразу открывает системный диалог, без промежуточных окон или вкладок. Ссылка на выбранную папку сохраняется в IndexedDB расширения, а её название — в локальных настройках. Выбор сохраняется при перезагрузке страницы и перезапуске браузера; Chrome может повторно запросить разрешение на запись. Полный путь к папке браузер не раскрывает, поэтому поле показывает её название. Файлы при выборе папки не создаются.

Для работы используется текущая авторизация вкладки Яндекс Диска. Отдельный вход и экспорт cookies не требуются.

Оригинал записывается потоком в выбранную папку. Галочка в правом верхнем углу превью появляется только после закрытия потока и проверки размера сохранённого файла; крестик означает ошибку сохранения. Во время записи показывается многоточие. Отметки сохраняются в IndexedDB расширения отдельно для разных аккаунтов и восстанавливаются после обновления страницы. Сломанное превью также получает отметку.

До открытия просмотрщика повторный запуск пропускает успешные файлы, если выбрана та же папка, совпадает идентификатор превью с историей или JSON, файл существует и его размер и локальная дата изменения совпадают с сохранёнными. Ошибки пробуются повторно. Существующие файлы не перезаписываются: при совпадении имени добавляется суффикс `(2)`, `(3)` и далее. Одновременно допускается одна загрузка во всех окнах расширения.

Закрытие панели или вкладки прерывает работу. При следующем открытии панели неподтверждённые сохранения отмечаются ошибкой. Если Яндекс не вернул адрес оригинала за 30 секунд, загрузка останавливается; перед повторным запуском нужно обновить страницу. При сетевом ограничении HTTP 429, отказе доступа или ошибке записи расширение останавливается, а не создаёт серию повторных запросов.

### Даты файлов

Имя берётся из информационного блока Яндекса. После каждого успешного сохранения рядом с фото и видео обновляется `yandex-downloads.json`: идентификатор аккаунта/файла, исходное и фактическое имя (с учётом коллизий), тип, размер, исходные строки «Создан» / «Изменён», даты в UTC и время изменения при сохранении. Подписанных URL и cookies в JSON нет. Даты Яндекса трактуются в часовом поясе браузера; UTC сохраняется, чтобы последующее применение не зависело от часового пояса системы.

Chrome сам не назначает системные даты: [File System Access](https://fs.spec.whatwg.org/#api-filesystemwritablefilestream) не предоставляет этой операции. Расширение определяет ОС через `runtime.getPlatformInfo`, сохраняет рядом скрипт и после завершения или остановки показывает команду. Откройте терминал **в выбранной папке**:

| ОС | Команда | Какие даты применяются |
| --- | --- | --- |
| Windows | `powershell.exe -NoProfile -File .\yandex-apply-dates.ps1` | Создание и изменение |
| macOS | `osascript -l JavaScript ./yandex-apply-dates.js "$PWD/yandex-downloads.json"` | Создание и изменение через Foundation |
| Linux | `sh ./yandex-apply-dates.sh` | Изменение; используются системные `touch` и `stat` |

Команды для копирования (запускайте **в папке со скачанными файлами**, где находятся `yandex-downloads.json` и сохранённый расширением скрипт):

**Windows — PowerShell:**

```powershell
powershell.exe -NoProfile -File .\yandex-apply-dates.ps1
```

**macOS — Терминал:**

```sh
osascript -l JavaScript ./yandex-apply-dates.js "$PWD/yandex-downloads.json"
```

**Linux — терминал:**

```sh
sh ./yandex-apply-dates.sh
```

PowerShell и macOS читают JSON; для Linux команды генерируются из тех же записей JSON без Python и jq. Скрипты проверяют имена, обычный тип и размер файла, не следуют символическим ссылкам и сообщают об ошибках. На Windows политика запуска PowerShell может запретить скрипт; команда не ослабляет её. Поддержка и точность дат зависят от файловой системы. [Foundation](https://developer.apple.com/documentation/foundation/filemanager/setattributes(_:ofitematpath:)) поддерживает обе даты на macOS; на Linux обычными средствами дата создания не устанавливается. Не запускайте команду одновременно со скачиванием.

При повторном запуске сведения о ранее скачанных файлах из истории добавляются в JSON без скачивания. JSON тоже используется для восстановления продолжения, если внутренняя история утрачена. Файл пропускается только при совпадении источника, имени, папки, размера и времени изменения — исходного при сохранении либо применённого из JSON. Отсутствующие или изменённые файлы загружаются снова. Чужой или повреждённый JSON/скрипт не перезаписывается; изменение JSON другой программой останавливает запись, чтобы сохранить чужие данные.

### Проверки и ограничения

Если сервер не отвечает или не передаёт следующий блок данных 30 секунд, запрос текущего файла отменяется. Незавершённая запись не считается успешной, пустой файл удаляется, очередь переходит к следующему оригиналу; повторный запуск попробует неудачный файл снова. Это таймаут отсутствия данных, а не ограничение общей длительности: большие видео могут скачиваться дольше. Кнопка остановки прерывает ожидание ответа/данных. Панель показывает получение адреса, ожидание данных и обновление истории/JSON.

Локальные тесты покрывают обход подгружаемой ленты, фильтры, остановку, ошибки сети/записи, коллизии имён, повторный запуск и сохранение истории. В видимом Chrome проверено реальное сохранение оригиналов HEIC и MOV в выбранную папку, чтение дат и отметки на превью. Полный массовый экспорт аккаунта не проверен.

Интеграция зависит от DOM Яндекс Диска и его элемента `download-iframe`. При изменении интерфейса расширение может потребовать обновления. Кнопка «Остановить скачивание» завершает текущую работу; «Начать / продолжить скачивание» заново обходит ленту и пропускает проверенные оригиналы. После сбоя незавершённые записи повторяются. На время работы не меняйте аккаунт и не переключайте страницу Яндекс Диска. Папка и история хранятся локально; удаление расширения удаляет историю.

## Стек

- TypeScript и React.
- [WXT](https://wxt.dev/) со сборкой на Vite.
- Chrome Extensions Manifest V3.
- Обычный CSS для оформления.

Сервер и дополнительные программы для скачивания не требуются. Подписанный адрес оригинала используется только в памяти и не записывается в историю. Разрешения ограничены настройками, боковой панелью, выполнением кода на странице Диска и получением оригиналов с серверов Яндекса.

## Разработка

Требуется Node.js 22.12 или новее и npm.

Для установки расширения требуется Google Chrome 116 или новее.

```bash
npm ci
npm run dev
```

WXT запускает браузер с расширением для разработки.

Доступные команды:

```bash
npm run typecheck # Проверка типов
npm run build     # Сборка для Chrome
npm test          # Сборка и тесты расширения
npm run check     # Проверка типов, сборка и тесты
npm run zip       # Упаковка расширения
```

## Установка локальной сборки

1. Выполнить `npm run build`.
2. Открыть `chrome://extensions` в Google Chrome.
3. Включить «Режим разработчика».
4. Нажать «Загрузить распакованное расширение» и выбрать папку `.output/chrome-mv3`.
5. Обновить вкладку Яндекс Диска после установки или обновления расширения. В разделе «Фото» нажать на значок расширения или кнопку «Скачать все», чтобы открыть правую панель.

Если файл уже есть в папке, но история и JSON о нём отсутствуют, расширение читает информацию Яндекса и сравнивает оригинал побайтово с локальным файлом. При совпадении сохраняет его метаданные в JSON и удаляет временную копию. Эта первая проверка требует передачи оригинала и свободного места для временной копии; следующие запуски пропускают файл до открытия просмотрщика. При несовпадении исходный локальный файл остаётся нетронутым, оригинал сохраняется с суффиксом.

### Журнал для диагностики

В панели есть кнопка «Сохранить журнал ошибок». Она выгружает `yandex-download-debug-…json` стандартным способом Chrome. Журнал хранится локально в расширении и переживает закрытие панели и перезапуск браузера: последние 50 ошибок и состояние текущего/последнего запуска. Для каждой ошибки сохраняются этап, имя файла, состояние сети, счётчики, положение прокрутки, число распознанных и видимых элементов, примеры неопознанных превью и до 120 последних сетевых событий этого файла/этапа.

Во время скачивания расширение наблюдает запросы выбранной вкладки к Диску, серверам оригиналов и превью, а также собственные запросы оригиналов. Записываются метод, время, HTTP-статус, сетевые ошибки, перенаправления и заголовки типа/размера ответа. Для `models-v2` при нажатии «Скачать» дополнительно сохраняется сводка ответа: наличие `file`/`digest`, имя, размер, тип содержимого и признак ошибки. Статус 200 не считается подтверждением сохранения оригинала. При ошибке получения оригинала сохраняется до 2048 символов текста ответа с очисткой URL и токенов. Полные тела запросов/ответов, cookies, авторизационные заголовки, идентификаторы аккаунта и подписанные URL не выгружаются. Журнал содержит имена ваших файлов; проверяйте их перед публикацией.

Сбор начинается с запуска скачивания: предыдущие ошибки без журнала восстановить нельзя. Нужны разрешение `webRequest` и доступ к поддоменам серверов превью; наблюдение не блокирует сетевые запросы. Журнал ограничен, поэтому не является полной записью всего сетевого трафика или HAR. После сбоя сохраните журнал и приложите его для анализа. Он поможет отличить остановку обхода ленты, отсутствие перехвата ссылки при ответе `mpfs/url` 200 и ошибку передачи/записи оригинала.

Повторный обход ускорен: для уже проверенных файлов не перезаписываются JSON, сценарий дат и внутренняя история на каждом пропуске. Восстановление отсутствующих записей истории и JSON сохраняется. Передача новых оригиналов остаётся последовательной; скорость сети и сервера этим изменением не увеличивается.

При ошибке журнал также автоматически записывается в выбранную папку рядом с оригиналами: `yandex-download-errors-<идентификатор запуска>.json`. Он обновляется после каждой ошибки и после завершения/остановки этого запуска. Для нового запуска создаётся отдельный файл при первой ошибке; успешный запуск не создаёт лишний журнал. При отсутствии доступа или ошибке записи журнал остаётся во внутреннем хранилище расширения, а панель показывает причину. Существующие чужие или изменённые извне журналы не перезаписываются. Внезапное закрытие браузера может прервать обновление файла; предыдущая завершённая запись и внутренняя история сохраняются.

Если `mpfs/url` вернул успешный ответ со ссылкой, но Яндекс не передал адрес в `download-iframe` за одну секунду, расширение использует ссылку API: сначала `digest`, затем `file`, если `digest` отсутствует. Адрес должен вести на HTTPS `downloader.disk.yandex.ru`, имя должно совпадать с текущим файлом, а просмотрщик — оставаться на выбранном оригинале. Скачивание по ссылке выполняется тем же механизмом записи и проверки файла в выбранной папке. Поздний браузерный запрос этого оригинала подавляется, чтобы не создать дубликат; событие `api-fallback` отмечается в журнале. После такого запасного пути ручное скачивание этого же файла кнопкой Яндекса снова доступно после обновления вкладки.

Ответы API наблюдаются с начала загрузки страницы: после обновления расширения обновите вкладку Яндекса. Событие `selected-link` показывает источник (`browser`/`api`) и поле (`digest`/`file`/`unknown`). Если браузерная ссылка возвращает HTTP 5xx и API дал другой `digest`, выполняется одна резервная попытка; события `api-retry` и `api-retry-succeeded` показывают её результат. Успешно восстановленная ошибка также записывается в журнал рядом с файлами. Ошибки записи на диск и остановка пользователя не запускают повторную попытку.

Отсутствующее превью обычного файла не блокирует всю фотоленту: расширение получает его идентификатор, имя и даты через просмотрщик. Если определить файл не удалось, он отмечается крестиком, остальные файлы обрабатываются дальше. В конце панель сообщает о необработанных файлах, а журнал содержит `unresolved` и `unresolvedCount`. Повторный запуск пробует их снова. Идентификаторы из просмотрщика кешируются только для того же элемента, имени и аккаунта; при обновлении вкладки файл без идентификатора превью может потребовать открытия просмотрщика для проверки.
